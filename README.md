# ai-factory-film

Съёмка видео-демо фабрики ПО на ИИ ([ai-factory](https://github.com/ypolosov/ai-factory)): ИИ-персонажи играют команду, режиссёр ведёт их по сценарию, камера снимает экраны, из журнала дубля собирается ролик.

Съёмка - отдельная система. Она не берёт ключей фабрики, не импортирует её код и не знает её внутренностей. О фабрике съёмка знает только её видимые выходы: метки задач, статусы коммитов, ответы и объявления бота. Перечень этих выходов фабрика ведёт у себя (`docs/demo/visible-outputs.md` в ai-factory) и проверяет своим контрактным тестом; здесь он - [src/contract.ts](src/contract.ts).

## Как устроено

- [film/film.yml](film/film.yml) - сценарий съёмки: участники, шаги, итоги шагов, кадры. Заготовки PR и вложений - [film/film-assets/](film/film-assets/), аватарки персонажей - [film/avatars/](film/avatars/).
- [src/film.ts](src/film.ts) - режиссёр и камера (Playwright без окна).
  - Участник шага действует своей учёткой: бот Discord, Atlassian, приложение GitHub.
  - Итог шага ждётся по связи с объектом дубля, а не по фразе фабрики: ответ на сообщение шага, ключ задачи и её связи, номер PR и статус на нужном коммите, тег.
  - Сбой команды, метка провала агента, красный статус там, где нужен зелёный, - провал шага сразу, с причиной.
  - Слияние PR - через ворота ветки, как у людей: ждём, пока обязательные проверки зелёные и PR не черновик; красная обязательная проверка или конфликт - провал шага. Так же сброс сливает PR возврата к базе демо.
  - Шаг сценария - план: предусловие (итоги других шагов, на которые он опирается), действие, ожидаемое событие, клипы. Журнал дубля (`manifest.json`) пишется после действия и после каждого плана: попытки планов с исходом и причиной, события, ссылки на объекты дубля, клипы по порядку сценария, версии съёмки, сценария, фабрики и цели на начало каждого запуска.
  - Прерванный или упавший план переснимается один: `--ctx` продолжает дубль в его каталоге, `--only` называет план. Пересъёмка начинается с частичного эффекта прошлой попытки: итог уже наступил - действие не повторяется, снимаются только кадры; остановка съёмки (`docker stop`, Ctrl-C) записывает попытку как прерванную.
  - Мир дубля свой: всё, что дубль создаёт или видит (задачи, страницы, PR), получает метки `film` и имени дубля; ожидание, выбравшее объект другого дубля, - провал шага. Ключ дубля `{takeKey}` делает объект дубля своим там, где площадка склеивает похожие (сбой в GlitchTip).
  - Базу демо заводит владелец, а в дублях пишут фабрика и персонажи: объект дубля - с меткой `film` или заведённый не владельцем (автор главной страницы пространства, руководитель проекта Jira). Свои страницы, например заметки о выпуске, фабрика ставит без меток съёмки - сброс уводит их в архив по автору.
  - Переписка в Discord попадает в ролик клипом чата: камера берёт настоящие сообщения шага (реплику участника, ответ фабрики, её объявление - по id и связям из журнала, ботом камеры) и показывает их в нейтральном виде чата с подписью источника и пометкой, кто ИИ-персонаж, кто фабрика, кто вебхук без учётки. Клип снимается в дубле после кадров шага; для снятого дубля - режимом `--chat`, без действий участников.
  - Окно Discord в ролике пишет OBS (решение владельца 18.10, [scripts/demo-discord.sh](scripts/demo-discord.sh)): окно Discord в браузере ([scripts/discord-browser.sh](scripts/discord-browser.sh): Edge в режиме приложения, свой профиль и порт отладки, вход владелец делает сам один раз) переходит по адресу первого сообщения шага (id - в журнале), свёрнутое окно разворачивается, захват окна OBS направляется на это окно по заголовку и вписывается в холст, и запись встаёт в журнал вместо клипа чата; чёрные кадры (окно потеряно) - запись повторяется. От учётки владельца ничего не пишется, но переходы запускает скрипт - серая зона правила 14 Discord, выбранная владельцем. Нет OBS - в роликах остаётся клип чата.
  - Figma снимает камера, как остальные сайты: холст без окна рисуется секунд 15-20, кадр его ждёт, нарезка берёт клип с конца.
  - Новый дубль начинается с проверки готовности мира, только чтением: стенд выложен с вершины main, нет открытых PR и задач прошлых дублей, нет их страниц вне архива, нет нерешённых сбоев стенда, входы камеры действуют и принадлежат своим персонажам.
- [src/script.ts](src/script.ts) - сценарий и проверка его цельности до первого действия: участники и учётки, подстановки, видимые выходы, учётки камеры.
- [film/cuts.yml](film/cuts.yml), [src/cuts.ts](src/cuts.ts), [src/release.ts](src/release.ts) - ролики из журнала дубля: нарезки для инвестора, полный прогон, тизер, B2C и B2B по ролям - из каких клипов и слайдов, сколько секунд, что говорит голос. Слайды объясняют то, чего нет в кадрах (способы работы, роли, инструменты): разделы колоды Claude Design "Слайды видео-демо фабрики" лежат в [film/slides/](film/slides/), картинки из них собирает [scripts/slides-render.sh](scripts/slides-render.sh) без сети, шрифтами из [film/fonts/](film/fonts/) (OFL). Ролик - заставка (дата прогона, ИИ-персонажи, версии), части с голосом edge-tts и субтитрами, итог прогона; рядом - ссылки на задачи и PR для описания; журнал публикаций `releases.json` с отметкой версий.
  - Страж свежести: изменились сценарий или фабрика после дубля - нужен новый дубль; изменилась только нарезка - перевыпуск из журнала, без съёмки.
- [src/atlassian.ts](src/atlassian.ts), [src/discord.ts](src/discord.ts), [src/github.ts](src/github.ts) - тонкие клиенты площадок учётками съёмки. Повторяется только чтение и повторяемая правка; уже сделанное второй раз не делается.

## Учётки и состояние

Всё секретное - в `.state/` (git его не видит):

- `discord-<персонаж>.env` - боты персонажей ([scripts/persona-bot-add.sh](scripts/persona-bot-add.sh));
- `discord-camera.env` - бот камеры с правом читать содержимое сообщений ([scripts/camera-bot-add.sh](scripts/camera-bot-add.sh));
- `atlassian-<персонаж>.env` - учётки Atlassian персонажей ([scripts/persona-atlassian-add.sh](scripts/persona-atlassian-add.sh));
- `github-app-<персонаж>.env` и `.pem` - приложения GitHub персонажей ([scripts/persona-github-app-add.sh](scripts/persona-github-app-add.sh));
- `discord-webhook-<канал>.env` - вебхук самозванца ([scripts/film-webhook-add.sh](scripts/film-webhook-add.sh));
- `camera/*.json` - входы камеры под персонажами и на сайтах ([scripts/camera-login.sh](scripts/camera-login.sh));
- `glitchtip.token` - ключ сброса для сбоев стенда, по желанию;
- `obs.env` - запись окна Discord: `OBS_WS_PASSWORD` (сервер WebSocket OBS), по желанию `OBS_SCENE` и `OBS_WS_URL` (по умолчанию `ws://127.0.0.1:4455`; если Windows держит этот порт в резерве - `netsh int ipv4 show excludedportrange protocol=tcp`, - другой порт в OBS и здесь);
- `world.env` - мир съёмки: `ATLASSIAN_SITE`, `JIRA_PROJECT`, `CONFLUENCE_SPACE`, `GITHUB_TARGET_REPO`, по желанию;
- `films/<время>/` - клипы и журналы дублей;
- `releases/` - ролики, ссылки для описаний, журнал публикаций и кеш голоса.

Камера смотрит учётками из `camera` в сценарии: свой бот в Discord, учётки персонажей в Jira, Confluence и GitHub.

## Запуск

```sh
scripts/demo-reset.sh -n        # что сброс сделает перед дублем
docker run ... ai-factory-film/camera /film/film.yml /out --preflight   # только проверка готовности мира
scripts/demo-film.sh            # сброс и дубль целиком
scripts/demo-film.sh --ctx .state/films/<время>/manifest.json   # продолжить дубль с первого несделанного плана
scripts/demo-film.sh --ctx .state/films/<время>/manifest.json --only story   # переснять один план
scripts/demo-film.sh --ctx .state/films/<время>/manifest.json --chat   # клипы чата для снятого дубля
scripts/demo-cut.sh .state/films/<время>                        # черновая склейка из журнала
scripts/discord-browser.sh        # окно Discord для записи через OBS (первый раз - вход в Discord)
scripts/demo-discord.sh .state/films/<время>   # окно Discord через OBS вместо клипов чата
scripts/slides-render.sh          # картинки слайдов из film/slides/*.html
scripts/demo-release.sh --check   # страж свежести роликов: 0 - свежие, 1 - перевыпуск, 3 - нужен новый дубль
scripts/demo-release.sh           # ролики одной командой: новый дубль, если нужен, и сборка из журнала
scripts/demo-release.sh --from-journal .state/films/<время>   # ролики из этого дубля, без новой съёмки
```

Фабрика и стенд цели должны уже работать: их поднимает ai-factory.

## Публикация

- Пометки ИИ в самих роликах: в заставке - роли играют ИИ-персонажи, работу фабрики делает ИИ, голос - синтез речи; на кадрах - плашка "ИИ-персонаж"; в чате - роль каждого автора; в метаданных файла - машиночитаемая пометка.
- YouTube (правила на 10.2026): пометка "изменённый или синтетический контент" обязательна для реалистичного контента, который можно принять за настоящий (клон голоса человека, поддельная съёмка); озвучка явно синтетическим голосом, никого не изображающим, её не требует. Ставить её всё равно разумно - роли играют ИИ-персонажи.
- Россия (10.2026): обязательного закона о маркировке ИИ-контента нет; по законопроекту обязательна машиночитаемая метка, видимая - по соглашению площадки и пользователя. Обе в роликах есть.
- Описание ролика - из `<ролик>-links.md`: прогон, версии, ссылки на задачи и PR.
- В Discord пишут только боты и вебхуки (правило 14 Discord); окно Discord в браузере OBS только записывает, переходы к сообщениям - по их адресам (решение владельца 18.10).

## Проверки

`make check` - скрипты (shellcheck, shfmt), `make test` - типы, стиль (Biome) и тесты (Vitest) в Docker, как в CI. Тест границы не пускает в код и скрипты съёмки ключи и код фабрики.
